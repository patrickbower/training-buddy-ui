# Domain Model

These are the canonical entity names used throughout the codebase. Consistency here matters — agents should use these names exactly in types, variables, and API routes.

All types are defined in `src/types/domain.ts`.

## Entities

### Athlete

The authenticated user. Contains profile information, fitness context, and goals.

```ts
interface Athlete {
  id: string
  stravaId: string // Strava OAuth user ID
  name: string
  email: string
  avatarUrl: string | null
  fitnessLevel: 'beginner' | 'intermediate' | 'advanced'
  weeklyMileageTarget: number // in km
  goals: AthleteGoal[]
  createdAt: string // ISO 8601
}
```

### TrainingPlan

A structured multi-week plan generated by the AI coach. Belongs to one Athlete.

```ts
interface TrainingPlan {
  id: string
  athleteId: string
  name: string
  description: string
  startDate: string // ISO 8601 date (YYYY-MM-DD)
  endDate: string
  sessions: Session[]
  status: 'active' | 'completed' | 'paused'
  createdAt: string
}
```

### Session

A single planned workout within a TrainingPlan. Has a target but no actual data until completed.

```ts
interface Session {
  id: string
  planId: string
  date: string // ISO 8601 date (YYYY-MM-DD)
  type: 'easy' | 'tempo' | 'interval' | 'long' | 'rest' | 'race'
  targetDistanceKm: number | null
  targetPacePerKm: string | null // e.g. "5:30"
  notes: string
  completedRunId: string | null // null until athlete logs a Run
}
```

### Run

A completed workout logged by the athlete (or imported via Strava).

```ts
interface Run {
  id: string
  athleteId: string
  sessionId: string | null // null if not linked to a plan
  date: string // ISO 8601 date
  distanceKm: number
  durationSeconds: number
  averagePacePerKm: string // e.g. "5:45"
  averageHeartRate: number | null
  maxHeartRate: number | null
  elevationGainM: number | null
  perceivedEffort: 1 | 2 | 3 | 4 | 5 | null
  stravaActivityId: string | null
  createdAt: string
}
```

### Conversation

The thread of messages between the athlete and the AI coach. One active conversation per athlete.

```ts
interface Conversation {
  id: string
  athleteId: string
  messages: CoachMessage[]
  createdAt: string
  updatedAt: string
}
```

### CoachMessage

A single message within a Conversation. Can be from the athlete or the AI coach.

```ts
interface CoachMessage {
  id: string
  conversationId: string
  role: 'athlete' | 'coach'
  content: string
  createdAt: string
}
```

### AthleteGoal

A goal attached to an Athlete. Used by the coach to personalise plans.

```ts
interface AthleteGoal {
  id: string
  type: 'race' | 'distance' | 'consistency' | 'weight_loss' | 'general_fitness'
  description: string
  targetDate: string | null
}
```

## Naming conventions

- IDs are always `string` (UUID format from the backend).
- Dates are always `string` in ISO 8601 format. Never `Date` objects in API responses.
- Distance is always in **kilometres**. Speed/pace is always **per km**.
- Duration is always in **seconds**.
