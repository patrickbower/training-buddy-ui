# Ubiquitous Language

## People

| Term        | Definition                                                             | Aliases to avoid             |
| ----------- | ---------------------------------------------------------------------- | ---------------------------- |
| **Athlete** | The authenticated user — holds profile, fitness context, and goals     | User, runner, person, client |
| **Coach**   | The AI that generates plans and responds to messages in a Conversation | Bot, assistant, AI, model    |

## Training

| Term                | Definition                                                                                        | Aliases to avoid               |
| ------------------- | ------------------------------------------------------------------------------------------------- | ------------------------------ |
| **TrainingPlan**    | A structured multi-week plan generated by the Coach for one Athlete                               | Plan, programme, schedule      |
| **Session**         | A single planned workout within a TrainingPlan — has targets but no actuals until a Run is logged | Workout (planned), event, slot |
| **Run**             | A completed workout logged by the Athlete or imported from Strava                                 | Activity, workout (completed)  |
| **AthleteGoal**     | A goal attached to an Athlete used by the Coach to personalise a TrainingPlan                     | Target, objective              |
| **FitnessLevel**    | A three-tier self-assessment of an Athlete: `beginner`, `intermediate`, or `advanced`             | Ability, skill level           |
| **SessionType**     | The training intent of a Session: `easy`, `tempo`, `interval`, `long`, `rest`, or `race`          | Run type, workout type         |
| **PlanStatus**      | The lifecycle state of a TrainingPlan: `active`, `completed`, or `paused`                         | State, status                  |
| **PerceivedEffort** | A 1–5 subjective effort rating logged on a completed Run                                          | RPE, effort score              |

## Conversation

| Term             | Definition                                                                          | Aliases to avoid            |
| ---------------- | ----------------------------------------------------------------------------------- | --------------------------- |
| **Conversation** | The single persistent thread of messages between one Athlete and the Coach          | Chat, thread, session       |
| **CoachMessage** | A single message within a Conversation, authored by either the Athlete or the Coach | Message, chat message, turn |
| **MessageRole**  | The sender of a CoachMessage: `athlete` or `coach`                                  | Author, sender, direction   |

## Integrations

| Term                 | Definition                                                                    | Aliases to avoid |
| -------------------- | ----------------------------------------------------------------------------- | ---------------- |
| **Strava**           | The third-party fitness platform used for OAuth authentication and Run import | External service |
| **stravaActivityId** | The Strava-side identifier for a Run imported from Strava                     | External ID      |

## Relationships

- An **Athlete** has one active **Conversation** and zero or more **TrainingPlans**.
- A **TrainingPlan** belongs to exactly one **Athlete** and contains one or more **Sessions**.
- A **Session** belongs to exactly one **TrainingPlan** and may link to at most one **Run** (via `completedRunId`).
- A **Run** belongs to one **Athlete** and optionally links to one **Session** — a **Run** with no `sessionId` is an unplanned run.
- A **Conversation** belongs to one **Athlete** and contains ordered **CoachMessages**.
- An **Athlete** has zero or more **AthleteGoals**, which the **Coach** uses to personalise **TrainingPlans**.

## Example dialogue

> **Dev:** "When the Athlete asks for a new plan, does the Coach replace the existing TrainingPlan?"
>
> **Domain expert:** "No — the old plan gets its status set to `completed` or `paused`, then a new TrainingPlan is created. There's no destructive replace."
>
> **Dev:** "And if the Athlete logs a Run that matches a scheduled Session, how does that link up?"
>
> **Domain expert:** "The Run's `sessionId` is set, and the Session's `completedRunId` is filled in. Until that happens the Session is just a target — it has no actual data."
>
> **Dev:** "What about a Run imported from Strava that doesn't match any Session?"
>
> **Domain expert:** "It's still a valid Run — `sessionId` is null. The Coach can reference it in the Conversation but it sits outside the TrainingPlan."

## Flagged ambiguities

- **"workout"** appears in comments and conversation but is never a domain term. Use **Session** for a planned workout and **Run** for a completed workout.
- **"user"** is used loosely in the UI layer. The domain entity is always **Athlete** — reserve "user" only for auth/session concerns where no domain meaning is intended.
- **"chat"** and **"thread"** may surface in UI copy or API naming. The canonical term is **Conversation**; a single message within it is a **CoachMessage**.
